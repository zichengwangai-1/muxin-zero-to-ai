# 木辛-零基础学AI PRD（V1.1优化版）

| 项目 | 内容 |
|---|---|
| 产品名称 | 木辛-零基础学AI |
| 版本 | V1.1 / MVP |
| 日期 | 2026-08-30 |
| 核心用户 | 想用AI提升办公能力或转行AI产品经理的纯小白 |
| 核心结果 | 学得懂、做得出、能复用；转行用户还能形成作品集并提升面试表达 |
| 优化依据 | Product-Manager-Skills：AI能力设计、上下文工程、智能体编排 |

## 1. 产品定位

“木辛-零基础学AI”是一个面向纯小白的结果导向型AI学习网站。它不追求收录最多的工具、新闻和论文，而是帮助用户解决两类实际问题：

1. **办公提效**：学会用AI完成写作、信息整理、分析、表格、汇报等真实任务。
2. **转行AIPM**：掌握必要的产品与AI知识，完成实战项目，并形成作品集和面试能力。

产品主张：

> 不要求用户先学完大量理论，而是在完成一个个真实任务时，理解AI、使用AI，并产出能复用或展示的成果。

### 1.1 V1展示原则

- 不做入门测评。
- 不根据用户身份展示不同首页或不同课程。
- 不做个性化推荐和自动生成学习路线。
- 所有用户看到同一套目录，可按当前需求自由进入。
- 内容卡片只标注难度、时长、前置知识和产出，不标注“你是哪类用户”。

## 2. 用户问题与产品假设

### 2.1 用户问题

- AI内容散落在短视频、图文、课程、GitHub和资讯网站中，小白不知道先学什么。
- 很多教程展示工具功能，却没有提供完整输入、操作步骤、结果检查和复用方式。
- 用户收藏了大量Prompt和资料，但换一个任务就不会使用。
- 想转行AIPM的用户会背概念，却缺少可演示的项目和真实产品判断。
- 面经内容来源零散、时效不清，用户难以理解面试官考什么、答案如何记忆。

### 2.2 核心产品假设

如果网站按照用户要完成的事情组织内容，并让每个知识点都连接到具体任务、项目成果或面试表达，那么纯小白会比浏览普通课程目录更容易开始、更容易完成，也更容易获得可验证的学习成果。

### 2.3 V1需要验证的关键假设

1. 用户能否在10秒内理解网站能帮助自己完成什么。
2. 用户是否愿意从目录直接进入一个真实任务，而不是先寻找完整课程。
3. 办公教程能否让用户产出可立即复用的模板或结果。
4. AIPM内容能否推动用户从“看知识”进入“做项目”。
5. 用户完成项目后，能否用结构化方式讲清楚项目决策和AI方案。

## 3. 产品目标与非目标

### 3.1 V1目标

- 建立一套纯小白能直接使用的AI学习目录。
- 提供一批从输入到验证都完整的AI办公任务教程。
- 建立AIPM知识、真实面经、项目和作品集之间的关联。
- 提供两个可实际完成和展示的AIPM实战项目。
- 建立支持Excel批量导入、人工审核和持续更新的内容后台。
- 为后续RAG预留结构化内容、来源和质量字段，但不把RAG作为V1核心功能。

### 3.2 V1非目标

- 不覆盖算法工程、模型训练和学术研究。
- 不做大而全的AI工具导航、Prompt大全或普通资讯站。
- 不做用户分层、个性化首页和个性化推荐。
- 不做社区、直播课、付费体系、证书和招聘撮合。
- 不做全自动采集、自动发布和无人审核的AI内容流水线。
- 不做用户账号、跨设备进度和个人知识库。

## 4. 核心用户

V1只定义一个统一核心用户：**零基础AI学习者**。

典型特征：

- 不理解大模型、Token、RAG、Agent等术语。
- 不擅长写复杂Prompt，也不具备开发经验。
- 希望用AI提高日常办公效率，或准备转行AI产品经理。
- 更需要明确步骤、可复制模板和完成标准，而不是抽象理论。
- 可投入时间有限，希望快速看到实际成果。

网站不根据“办公提效”或“转行AIPM”改变展示方式；二者只是同一目录中的不同需求入口。

## 5. 用户结果与能力地图

Product-Manager-Skills强调从“会用工具”升级为“能够设计稳定的人机工作方式”。V1不做能力测评，但用以下能力地图约束课程和项目内容。

| 能力 | 小白需要达到的结果 | 网站中的证明方式 |
|---|---|---|
| AI基础认知 | 能解释模型能做什么、不能做什么 | 知识卡片练习与场景判断 |
| 任务拆解 | 能把模糊任务拆成清晰输入、步骤和产出 | 办公任务模板、项目流程 |
| 上下文设计 | 知道该给AI哪些资料，哪些资料不需要 | Prompt说明、Context清单、RAG项目 |
| 人机协作 | 知道哪些步骤交给AI，哪些必须人工判断 | 工作流图、人工检查点 |
| AI产品设计 | 能从用户问题设计AI功能和交互 | 两个AIPM项目交付物 |
| 质量评测 | 能定义“回答好不好”，并记录错误 | 测试集、评测表、失败案例 |
| 风险与约束 | 能考虑幻觉、隐私、版权、成本和延迟 | 项目风险清单与迭代方案 |
| 项目表达 | 能用证据解释为什么这样设计 | 作品集、30秒/3分钟项目表达 |

每篇核心内容至少说明：用户学完能完成什么、如何检查结果、能用在哪个真实场景。

## 6. 整体板块设计

网站由一个统一首页和两个核心板块组成：

```text
首页：按需求开始
├── AI学习区
│   ├── AI入门
│   ├── AI办公提效
│   └── AI产品经理学习
│
└── AI项目实战
    ├── 办公任务实操
    └── AIPM完整项目
```

### 6.1 首页：按需求进入

首页提供六个固定入口，所有用户看到的内容完全一致：

| 用户当前需求 | 进入目录 | 首屏说明 |
|---|---|---|
| 我想从零了解AI | AI入门 | 用简单例子理解AI，不先学复杂技术 |
| 我想用AI提升办公效率 | AI办公提效 | 跟着步骤完成一个真实办公任务 |
| 我想了解AI产品经理 | AIPM岗位与基础 | 了解工作内容和必备能力 |
| 我想学习AI产品知识 | AIPM核心知识 | 学习RAG、Agent、评测等必要知识 |
| 我想完成AI项目 | AI项目实战 | 做出可演示、可复盘的项目 |
| 我想准备作品集和面试 | AIPM求职准备 | 整理项目、回答问题、练习追问 |

每个入口显示三项信息：适合解决的问题、预计用时、完成后能得到什么。

### 6.2 AI学习区

#### A. AI入门

- AI和大模型是什么。
- 模型能做什么、不能做什么。
- Prompt、上下文、Token的基本概念。
- 如何检查AI回答，而不是直接相信。
- 隐私、版权和敏感信息基础。

#### B. AI办公提效

按工作任务组织，不按工具品牌组织：

- 写作与改写。
- 资料检索与信息整理。
- 会议纪要与行动项。
- 表格分析与数据解释。
- 汇报框架与演示文稿。
- 重复工作流程化。

每个办公任务使用统一模板：

```text
任务场景
→ 准备哪些材料
→ 可直接使用的Prompt
→ 分步操作
→ 如何检查结果
→ 常见错误
→ 如何保存为自己的模板
```

#### C. AI产品经理学习

- AIPM岗位认知与工作流程。
- 产品经理必要基础：问题定义、需求、方案、MVP、指标、PRD。
- AI产品核心知识：模型、RAG、Agent、多模态、评测。
- AI产品工作方法：上下文、工作流、人机边界和风险。
- 面试题与真实面经。
- 与项目和面试相关的模型、论文及行业动态。

每篇AIPM知识内容使用统一模板：

```text
一句话解释
→ 小白例子
→ 产品中怎么用
→ 怎么判断做得好不好
→ 面试怎么问
→ 30秒回答框架
→ 常见追问
→ 关联项目
```

### 6.3 AI项目实战

#### A. 办公任务实操

以30—90分钟可完成的小任务为主。每个任务必须产出一个可继续使用的模板、文档、表格、演示稿或工作流。

#### B. AIPM完整项目

项目学习闭环：

```text
用户问题
→ 为什么使用AI
→ 产品方案
→ 上下文与数据
→ 搭建与测试
→ 评测与错误分析
→ 迭代
→ 作品集
→ 面试表达
```

每一步都说明：要完成什么、为什么这样做、需要哪些材料、完成标准是什么、面试官可能如何追问。

## 7. 首发内容范围

### 7.1 AI办公任务（P0）

首发至少12个高频任务，覆盖以下四组：

1. **写作**：邮件、方案初稿、内容改写。
2. **整理**：会议纪要、长文总结、信息对比。
3. **分析**：表格解读、问题归类、结论提炼。
4. **汇报**：汇报框架、PPT大纲、口头表达准备。

选择标准：使用频率高、输入材料容易获得、结果容易验证、不依赖付费或小众工具。

### 7.2 AIPM首发项目（P0）

#### 项目一：AIPM面试资料智能助手

将结构化面经变成可检索、可追溯的学习与回答系统。

覆盖：需求分析、内容后台、数据结构、上下文设计、RAG、引用、幻觉控制、回答评测、成本与人工审核。

#### 项目二：AI用户反馈分析助手

输入评论、客服记录或问卷，输出分类、主题、情绪和需求建议。

覆盖：分类体系、AI与人的边界、Prompt、结构化输出、黄金样本、人工抽检、失败案例和产品建议。

项目一为完整跟做型；项目二为半开放型，要求用户自行完成部分产品决策。

## 8. 核心功能需求

### 8.1 首页与目录（P0）

- 展示产品定位、六个需求入口和两个核心板块。
- 不要求用户注册、测评或选择身份。
- 支持按主题、难度、预计时长和内容类型筛选。
- 内容卡片显示“要解决的问题”和“最终产出”。
- 允许用户返回上次浏览位置；仅使用浏览器本地记录。

**验收：** 新用户在10秒内理解网站用途；任一入口不超过2次点击到达内容；移动端和桌面端目录可正常使用。

### 8.2 内容详情（P0）

- 支持知识卡片、办公任务、面试题和项目步骤四种内容模板。
- 展示前置材料、预计时长、完成标准和关联内容。
- 支持复制Prompt、模板和回答框架。
- 支持勾选完成；进度保存在本地，不跨设备同步。

### 8.3 面试题库（P0）

- 按公司、岗位、轮次、主题和时间筛选。
- 展示题目、考察目的、小白解释、回答框架、30秒回答和常见追问。
- 展示来源平台、来源链接、发生时间和最后审核时间。
- 区分“原始资料中的事实”与“网站给出的分析或建议”。
- 关联相关知识和项目证据。

### 8.4 项目实战（P0）

- 展示项目最终效果和交付物清单。
- 分步骤展示材料、Prompt、操作、评测和完成标准。
- 提供需求分析、方案、评测记录和作品集模板。
- 提供30秒、3分钟项目表达及常见追问。
- 用户可重置项目进度。

### 8.5 搜索与关联（P0）

- 支持关键词搜索，结果区分知识、办公任务、面试题和项目。
- 支持基础标签筛选。
- 内容之间使用人工配置的关联关系。
- V1不使用向量检索，不生成AI搜索答案。

### 8.6 用户空间（P1）

- 账号、收藏、笔记和跨设备进度。
- 保存个人Prompt、办公模板、项目成果和面试回答。

### 8.7 RAG学习助手（P1）

- 只检索已经人工审核并允许对外使用的内容。
- 支持按内容类型、岗位、公司、主题、时间和来源可信度过滤。
- 回答必须展示引用内容和最后更新时间。
- 没有足够证据时返回“当前资料不足”，不拼凑答案。

### 8.8 模拟面试与作品集辅助（P2）

- 根据目标岗位和用户项目生成问题。
- 从结构、证据、产品判断和表达清晰度点评回答。
- 辅助整理作品集，但不编造用户经历、数据和个人贡献。

## 9. 内容与上下文工程

### 9.1 内容边界清单（Context Manifest）

| 类型 | 内容 | 使用方式 |
|---|---|---|
| 固定规则 | 术语表、回答模板、版权规则、证据标准 | 每次相关生成任务都提供 |
| 按需资料 | 具体面经、文章、项目案例、模型动态 | 根据当前问题检索少量相关内容 |
| 内部原始资料 | 原文、截图、视频字幕、处理备注 | 仅供清洗、审核和追溯 |
| 排除内容 | 无法确认来源、明显过时、互相冲突且未核实、含隐私的信息 | 不进入生成和前台展示 |

### 9.2 内容准入问题

任何内容进入前台前必须回答：

1. 它帮助用户完成哪个具体任务或决策？
2. 如果不提供这条信息，会产生什么明确问题？
3. 它是长期规则，还是只在特定问题下检索？
4. 来源是否可追溯，时间是否仍有效？
5. 哪些内容是事实，哪些内容是编辑判断？

### 9.3 来源质量字段

每条原始资料至少记录：

- `source_id`：唯一编号。
- `platform`、`source_url`、`author`、`published_at`。
- `content_type`：图文、视频、文档。
- `raw_content`：正文、OCR文字或视频字幕。
- `source_level`：官方、一手面经、二次整理、观点内容。
- `freshness_status`：有效、需复核、过时。
- `copyright_status`：可引用、仅内部、禁止展示原文。
- `confidence`：高、中、低，并记录判断理由。
- `reviewed_at`、`reviewer`、`processing_status`。

### 9.4 RAG上下文规则（P1）

- 固定上下文只保留产品规则、证据要求、术语和输出格式。
- 历史面经、论文、动态和项目案例全部按需检索。
- 检索前使用岗位、公司、时间、主题等结构化条件缩小范围。
- 不把整个资料库、完整长文或无关会话历史塞入模型。
- 回答生成后检查每个关键结论是否能被引用内容支持。
- 原始研究过程与最终回答分离，最终生成只使用压缩后的高密度资料。

### 9.5 RAG验收指标（P1）

- 引用可访问率：引用能回到有效内容。
- 引用支持率：关键结论能被引用资料直接支持。
- 检索命中率：测试问题能找到预期资料。
- 无答案安全率：资料不足时不编造。
- 新鲜度命中率：有新旧冲突时优先使用已审核的新内容。
- 单次回答使用的内容量、成本和延迟保持在设定预算内。

## 10. 后台管理与内容流水线

### 10.1 V1后台功能

- Excel批量导入原始资料和附件索引。
- 管理AI入门、办公任务、AIPM知识、面试题、项目和项目步骤。
- 管理来源、标签、关联关系和内容状态。
- 支持草稿、待审核、已发布、需复核、已下架。
- 支持预览、版本记录和最后审核时间。
- 支持标记重复、过时、来源冲突、隐私和版权风险。

### 10.2 内容流水线与交接标准

V1由人工主导；V2可将标准化环节交给多个Agent。各环节使用同一套交接结构：

| 环节 | 输入 | 输出 | 必须检查 |
|---|---|---|---|
| 导入 | Excel、链接、正文、字幕、附件 | 原始资料记录 | 来源和附件能否对应 |
| 清洗去重 | 原始资料 | 规范化、去重后的资料 | 是否误删不同语境内容 |
| 信息提取 | 规范化资料 | 公司、岗位、题目、主题候选 | 不得补写原文没有的事实 |
| 内容草拟 | 已确认的结构化资料 | 知识卡或面试题草稿 | 事实与编辑判断分开 |
| 质量检查 | 草稿与来源 | 问题清单、引用核对结果 | 来源、时效、隐私、版权 |
| 人工审核 | 草稿、来源、检查结果 | 可发布版本或退回原因 | 结论是否准确且适合小白 |
| 发布 | 已批准版本 | 前台内容与关联关系 | 页面、链接、标签是否正常 |

每一步只接收完成该任务需要的内容，不默认把所有历史资料传给下一步。

### 10.3 AI自动化边界

- AI可以辅助OCR整理、去重候选、字段提取、标签建议和内容草拟。
- AI不能自行确定面经真实性、版权状态和最终可信度。
- AI不能把推测写成公司真实招聘要求。
- AI不能自动发布或绕过人工审核。
- 发生来源冲突时必须进入“需复核”，不能自动选择结论。

### 10.4 内容质量评测

建立一组人工确认的代表性样本，用于检查AI辅助流程：

- 典型图文面经。
- 视频字幕面经。
- 同一问题的多个来源。
- 过时或互相冲突的内容。
- 含隐私和版权风险的内容。

重点监控四类错误：凭空补充事实、来源关联错误、过度概括个人经验、错误公开原始内容。

## 11. 内容数据模型

### 11.1 Source 原始资料

来源信息、原始内容、附件、质量字段、版权字段、处理状态和审核记录。

### 11.2 LearningContent 学习内容

- 类型：AI入门、办公任务、AIPM知识、行业解读。
- 标题、目标任务、难度、预计时长、前置材料。
- 小白解释、步骤、Prompt、检查方法、常见错误和完成标准。
- 关联面试题、项目和来源。

### 11.3 InterviewQuestion 面试题

题目、公司、岗位、轮次、主题、发生时间、考察目的、回答框架、30秒回答、深入回答、追问、来源和关联项目。

### 11.4 Project 项目

用户问题、AI适用性、产品方案、上下文与数据、步骤、交付物、测试集、评测、风险、迭代、作品集和项目表达。

### 11.5 Relation 内容关系

记录知识、办公任务、面试题和项目之间的关系及推荐理由，避免只靠相同标签进行模糊推荐。

## 12. 关键用户流程

### 12.1 办公提效

```text
首页点击“AI办公提效”
→ 选择真实任务
→ 准备输入材料
→ 复制Prompt并完成步骤
→ 按检查表核对结果
→ 保存为自己的复用模板
```

### 12.2 转行AIPM

```text
首页点击“了解AI产品经理”
→ 选择知识或项目
→ 学习必要概念
→ 完成项目步骤与评测
→ 整理作品集
→ 练习30秒/3分钟表达和追问
```

### 12.3 面试冲刺

```text
首页点击“作品集和面试”
→ 筛选面试问题
→ 理解考察目的
→ 练习回答框架和追问
→ 返回关联知识或项目补充证据
```

### 12.4 管理员更新内容

```text
导入资料
→ 清洗去重
→ 字段提取
→ 生成草稿
→ 来源和质量检查
→ 人工审核
→ 关联内容
→ 发布
```

## 14. 优先级与版本演进

### P0：内容MVP

- 所有用户共用同一首页和目录。
- AI入门、AI办公提效和AIPM学习内容。
- 12个办公任务、20篇AIPM核心内容、50道结构化面试题。
- 两个完整AIPM项目。
- 关键词搜索、基础筛选和人工关联。
- 本地学习进度。
- 内容后台、Excel导入、质量字段、审核和发布。

### P1：内容成熟后

- 用户账号、收藏、笔记、个人模板和跨设备进度。
- RAG学习助手、引用和检索评测。
- AI辅助回答练习。

### P2：规模化后

- 模拟面试和作品集辅助。
- 多智能体内容流水线与自动质量检查。
- 基于行为的个性化推荐。

P1、P2功能不得以不同首页、不同内容目录或不同用户身份作为V1前置条件。

## 15. 数据指标

### 15.1 北极星指标

每周完成一个“可验证成果单元”的独立用户数。

可验证成果单元包括：

- 完成一个办公任务并复制/下载可复用模板。
- 完成一个AIPM项目核心交付物。
- 完成作品集模板或3分钟项目表达。

### 15.2 过程指标

- 首页需求入口点击率。
- 内容开始率和完成率。
- Prompt或模板复制率。
- 知识到项目的跳转率。
- 项目步骤和交付物完成率。
- 作品集模板使用率。
- 面试题到关联知识/项目的回访率。
- 搜索无结果率。
- 内容审核通过率、返工率和过期内容数量。

### 15.3 首轮验证标准

至少邀请30名目标用户测试：

- 80%以上能在10秒内说出网站能帮助自己完成什么。
- 80%以上能在2次点击内找到办公任务或AIPM内容。
- 50%以上完成至少一个办公任务或一个项目核心步骤。
- 完成办公任务的用户中，60%以上认为结果可直接用于真实工作。
- 参与项目测试的用户中，60%以上能按模板完成一段3分钟项目介绍。

## 16. 风险与控制

| 风险 | 表现 | V1控制方式 |
|---|---|---|
| 定位变宽 | 办公内容与AIPM内容互相稀释 | 统一围绕“真实成果”，首页仅保留六个需求入口 |
| 内容过多 | 小白重新陷入选择困难 | 每个目录优先展示少量高频任务，限制V1数量 |
| 资料失真 | 把个人面经当成通用结论 | 标记来源等级、时间和可信度，人工审核 |
| AI幻觉 | 草稿出现来源没有的事实 | 事实与编辑判断分栏，逐条核对引用 |
| 内容过时 | 模型或面试信息失效 | 保存审核时间和有效状态，定期进入需复核 |
| 版权风险 | 直接搬运博主原文和图片 | 原始资料内部保存，前台发布提炼后的内容并保留来源 |
| 自动化失控 | Agent错误内容直接上线 | 所有内容必须经过人工审核，禁止自动发布 |

## 17. 上线验收标准

V1满足以下条件后进入种子用户测试：

- 产品名称统一为“木辛-零基础学AI”。
- 所有用户看到相同首页、目录和内容，不出现测评或差异化推荐。
- 六个需求入口均可在2次点击内到达目标内容。
- 至少12个办公任务包含输入、Prompt、步骤、检查和复用模板。
- 至少20篇AIPM核心内容符合统一学习模板。
- 至少50道面试题完成来源、时间、可信度和人工审核。
- 两个AIPM项目均包含问题、方案、上下文、评测、风险、作品集和面试表达。
- 管理员可完成Excel导入、清洗状态管理、编辑、审核、预览、发布和下架。
- 搜索能够区分办公任务、知识、面试题和项目。
- 原始资料和AI草稿不会未经审核出现在前台。
- 移动端和桌面端核心流程可正常使用。

## 18. 结论

“木辛-零基础学AI”的V1不靠个性化和复杂AI功能建立价值，而是靠一套清楚、可操作、能产生成果的内容系统：

```text
选择当前需求
→ 完成一个真实任务
→ 检查结果
→ 保存为可复用成果
→ 需要转行时继续进入项目、作品集和面试
```

结构化后台是V1的基础；RAG是内容成熟后的检索能力；多智能体是内容规模化后的生产效率。三者都不能替代人工判断、来源管理和真正适合小白的内容表达。

## 附录：Product-Manager-Skills在本PRD中的应用

- **AI能力设计**：用能力地图和可验证成果替代空泛课程目标，不引入用户测评。
- **上下文工程**：区分固定规则、按需资料、内部原文和排除内容，为RAG建立清晰边界。
- **智能体编排**：明确内容流水线各环节的输入、输出、检查点和人工审核责任；多智能体延后到P2。
