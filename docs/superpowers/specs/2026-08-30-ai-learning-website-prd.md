# AI学习网站 PRD（V1.0）

| 项目 | 内容 |
|---|---|
| 产品名称 | AI学习网站 |
| 版本 | V1.0 / MVP |
| 日期 | 2026-08-30 |
| 产品阶段 | 从0到1 |
| 核心方向 | 帮助零基础用户转行AI产品经理，并通过实战项目获得作品和面试能力 |

## 1. 产品概述

### 1.1 产品定位

AI学习网站是一套面向AI产品经理求职者的结果导向型学习平台。网站不追求收录最多的AI知识，而是帮助用户走完一条明确路径：

> 学会必要知识 → 完成AI项目 → 整理作品集 → 练习项目表达 → 准备真实面试。

第一版以两大板块为核心：

1. **AI产品经理学习区**：解决“需要学什么、如何理解、面试怎么回答”。
2. **AI项目实战**：解决“如何做出项目、如何形成作品、如何在面试中讲清楚”。

首页按用户当下需求导航，不设置入门诊断。用户可以直接点击“补基础、学AI产品、做项目、准备面试、做作品集”等入口。

### 1.2 核心价值

- 小白能看懂：先讲人话和案例，再讲专业概念。
- 学完能使用：每个知识点都关联项目任务。
- 做完能展示：每个项目都产出可放进作品集的材料。
- 面试能表达：每个重点都提供回答框架、记忆方法和追问练习。
- 内容可追溯：面经和外部资料保留来源、时间与可信度信息。

### 1.3 核心设计原则

1. **按用户目的组织，不按学科目录堆知识。**
2. **一个内容只解决一个明确问题。**
3. **知识、项目、作品集和面试相互关联。**
4. **原始资料用于内部加工，前台展示结构化、再创作后的学习内容。**
5. **第一版先建立高质量内容和结构化数据，再增加RAG和多智能体。**

## 2. 背景与用户问题

目前AI学习内容普遍存在以下问题：

- 内容分散在小红书、抖音、公众号、GitHub和课程平台中。
- 大量内容讲概念、模型和新闻，却没有告诉用户项目中如何使用。
- 面经真实性和时效性不明确，答案零散且难以记忆。
- 用户看过很多资料，但没有可以展示的项目和作品集。
- 用户会背概念，却无法回答“为什么这样设计、如何评测、哪里需要人工介入”等项目追问。
- 普通AI工具导航、Prompt合集与AIPM求职目标关联较弱，容易造成学习路径失焦。

## 3. 产品目标与非目标

### 3.1 V1目标

- 让纯小白能够按照目录找到适合自己的学习起点。
- 建立AIPM必要知识、真实面经和项目内容之间的关联。
- 提供两个从需求分析到作品集表达的完整实战项目。
- 建立可持续更新的内容后台与结构化面经资料库。
- 验证用户是否愿意沿“知识 → 项目 → 作品集 → 面试”完成连续学习。

### 3.2 V1非目标

- 不做覆盖所有AI职业的综合学习平台。
- 不做算法、模型训练和论文研究课程。
- 不做独立的Prompt大全、AI工具导航或普通AI新闻站。
- 不做社区、直播课、付费体系、证书和招聘撮合。
- 不做全自动内容采集和自动发布。
- 不把RAG问答作为首页核心入口。

## 4. 目标用户

### 4.1 第一优先级：纯小白

- 没有产品经理经验，也不理解AI基础概念。
- 想转行AIPM，但不知道学习顺序和岗位要求。
- 看过零散资料，却做不出项目、写不出作品集。
- 需要明确告诉他“学什么、做到什么程度、面试怎么说”。

### 4.2 第二优先级：传统产品经理

- 具备需求、方案、PRD等产品基础，但缺少AI产品经验。
- 希望直接学习RAG、Agent、模型选择、评测等AI产品能力。
- 需要用AI项目补充简历和作品集。

### 4.3 暂不重点服务

- 算法工程师、模型研究人员。
- 只想找AI工具或图片Prompt的普通用户。
- 企业级AI培训与团队管理者。

## 5. 用户核心任务

首页直接提供以下需求入口：

| 用户需求 | 进入位置 | 预期结果 |
|---|---|---|
| 我想了解AIPM | 岗位认知与学习路线 | 知道AIPM做什么、需要哪些能力 |
| 我想补产品基础 | 产品经理必备基础 | 掌握完成项目所需的基础方法 |
| 我想补AI知识 | AI产品核心知识 | 能理解并解释常见AI产品方案 |
| 我想做AI项目 | AI项目实战 | 完成可演示、可复盘的项目 |
| 我想准备面试 | 面试题与真实面经 | 能回答高频题并应对追问 |
| 我想制作作品集 | 项目成果与作品集 | 形成可投递的项目案例 |

用户无需完成测评，也无需从第一课顺序学习。每个入口应显示“适合谁、需要多久、完成后得到什么”。

## 7. 核心学习闭环

网站所有核心内容围绕同一闭环：

```text
知识卡片
   ↓
小练习/场景判断
   ↓
项目中的具体任务
   ↓
可保存的项目成果
   ↓
作品集案例
   ↓
项目面试表达与追问
```

每篇知识内容至少关联以下三项中的两项：项目步骤、面试问题、延伸知识。没有实际用途的知识不进入V1主路径。

## 8. 功能需求

### 8.1 首页与需求目录（P0）

**功能：**

- 展示一句清晰的产品定位。
- 提供六个需求入口，不要求用户先注册或测评。
- 展示两大核心板块及其完成成果。
- 展示两个首发项目及最终产出。
- 允许用户回到上次浏览位置；V1使用浏览器本地记录即可。

**验收标准：**

- 新用户在首页10秒内能够理解网站服务对象和主要结果。
- 任一核心需求可在不超过2次点击后到达对应内容目录。
- 移动端与桌面端均能清楚浏览目录。

### 8.2 AI产品经理学习区（P0）

#### 8.2.1 内容目录

- 支持按阶段、主题、难度、预计时长筛选。
- 清楚标记“纯小白必学”“传统PM可跳过”“面试高频”。
- 每个目录项展示完成后能解决的问题，不只显示课程名称。

#### 8.2.2 知识详情页

每篇知识内容使用统一结构：

1. 一句话解释。
2. 生活化或工作场景示例。
3. AIPM为什么需要懂。
4. 项目中如何使用。
5. 面试可能怎么问。
6. 30秒回答框架。
7. 记忆口诀、对比表或流程图。
8. 一道小练习。
9. 关联项目和延伸内容。

#### 8.2.3 面试题库

- 支持按公司、岗位、面试轮次、能力主题和时间筛选。
- 区分原始面经信息与网站加工后的学习内容。
- 展示题目、考察目的、小白解释、回答框架、30秒答案、深入答案和常见追问。
- 展示来源平台、原始链接和信息时间；不默认展示完整转载原文。
- 支持关联到知识卡片和项目步骤。

#### 8.2.4 模型、论文及动态

内容必须回答：

- 发生了什么。
- 小白需要理解什么。
- 对AI产品设计有什么影响。
- 面试可能怎么问。
- 可以用在哪个实战项目。

不满足以上条件的普通新闻不进入主站内容。

### 8.3 AI项目实战区（P0）

#### 8.3.1 项目详情

每个项目按以下结构呈现：

1. 项目目标与最终演示。
2. 目标用户和真实问题。
3. 为什么适合使用AI。
4. 产品方案与核心流程。
5. 必备知识。
6. 分步搭建过程。
7. Prompt、数据与工具。
8. 测试、评测和错误案例。
9. 方案迭代。
10. 作品集整理。
11. 30秒与3分钟项目介绍。
12. 面试官追问题库。

每一步都应包含“要完成什么、为什么这样做、直接可用的材料、常见错误、完成标准”。

#### 8.3.2 项目进度

- 用户无需登录即可勾选已完成步骤。
- 进度暂存在浏览器本地。
- 用户可重置单个项目进度。
- V1不提供跨设备同步。

#### 8.3.3 成果下载

- 提供需求分析、产品方案、评测记录和作品集模板。
- 用户可以复制模板或下载为常用文档格式。
- V1提供模板和填写指导，不自动生成完整作品集。

### 8.4 首发项目（P0）

#### 项目一：AIPM面试资料智能助手

**目标：** 将结构化面经资料变成可检索、可追溯的学习与回答系统。

**覆盖能力：**

- 用户需求与场景定义。
- 内容后台和数据结构。
- Prompt与上下文设计。
- RAG基础与检索逻辑。
- 来源引用与幻觉控制。
- 回答质量评测。
- 成本、延迟与人工审核。

#### 项目二：AI用户反馈分析助手

**目标：** 输入用户评论、客服记录或问卷内容，输出分类、情绪、主题和需求建议。

**覆盖能力：**

- 用户反馈数据结构。
- AI任务边界与人工职责。
- 分类体系与Prompt设计。
- 输出格式和异常处理。
- 黄金样本、人工抽检与质量指标。
- 从洞察到产品建议的判断过程。

第一个项目为完整跟做型；第二个项目为半开放型，要求用户自行完成部分产品决策。

### 8.5 搜索与关联推荐（P0）

- 支持站内关键词搜索。
- 搜索结果区分知识、面试题和项目。
- 支持基础标签筛选。
- 内容详情页展示人工配置的关联内容。
- V1使用数据库关键词检索和人工关联，不依赖向量检索。

### 8.6 用户账户与个人学习空间（P1）

- 注册与登录。
- 跨设备同步学习进度。
- 收藏、笔记和个人回答。
- 保存项目成果和作品集草稿。

### 8.7 RAG学习助手（P1）

RAG不是内容后台的替代品。它建立在已审核的结构化内容之上。

**能力：**

- 根据用户问题检索相关知识、面试题和项目材料。
- 回答时展示引用来源和内容更新时间。
- 允许按岗位、公司和面试轮次缩小检索范围。
- 找不到可靠资料时明确说明，不编造答案。

**上下文原则：**

- 固定提供：产品规则、回答格式、证据要求和术语定义。
- 按需检索：具体面经、历史文章、项目案例和模型动态。
- 不把整个内容库一次性塞给模型。
- 每次回答仅使用与当前问题直接相关的少量内容。

### 8.8 模拟面试与作品集生成（P2）

- 根据目标岗位和用户项目生成面试问题。
- 对回答进行结构、证据、产品判断和表达清晰度点评。
- 生成30秒、3分钟和追问版项目表达。
- 根据用户已有成果辅助整理作品集，但要求用户确认事实与个人贡献。

## 9. 后台管理系统

### 9.1 V1后台目标

后台首先解决“持续更新、审核、关联和追溯”，不承担自动采集所有平台内容的任务。

### 9.2 核心功能（P0）

- 管理知识文章、面试题、项目和项目步骤。
- 通过Excel批量导入原始面经资料。
- 管理标签、公司、岗位、轮次、能力主题和关联内容。
- 管理草稿、待审核、已发布、已下架状态。
- 保存原始来源链接、作者、发布时间、附件和内部备注。
- 支持预览前台展示结果。
- 支持修改记录和内容更新时间。

### 9.3 内容处理流程

```text
Excel/文档/链接导入
        ↓
进入原始资料库（内部）
        ↓
清洗、去重与结构化
        ↓
生成题目、考察点和回答草稿
        ↓
人工审核与修改
        ↓
关联知识和项目
        ↓
发布到前台
```

任何AI生成内容都必须经过人工审核后发布。

### 9.4 推荐导入格式

一条原始笔记占Excel一行，最低字段为：

| 字段 | 说明 |
|---|---|
| source_id | 唯一编号，如XHS-001 |
| platform | 小红书、抖音、飞书、ima等 |
| content_type | 图文或视频 |
| source_url | 原始链接 |
| title | 原始标题 |
| raw_content | 正文、OCR文字或视频字幕 |
| note | 人工备注，可为空 |
| attachment_names | 对应图片或字幕文件名 |

公司、岗位、面试轮次、题目和知识标签可由系统辅助提取，再由管理员确认。

## 10. 内容数据模型

### 10.1 原始资料 Source

- 来源编号、平台、URL、作者、发布时间。
- 图文/视频类型、原始文字或字幕、附件。
- 内部备注、版权状态、处理状态、重复标记。

### 10.2 知识内容 Knowledge

- 标题、分类、难度、适用人群、预计时长。
- 小白解释、案例、项目应用、记忆方式和练习。
- 关联项目、关联面试题、引用来源。
- 草稿/审核/发布状态和版本时间。

### 10.3 面试题 InterviewQuestion

- 题目、公司、岗位、轮次、时间和能力主题。
- 考察目的、小白解释、回答框架。
- 30秒答案、深入答案、常见追问。
- 来源、可信度、关联知识和关联项目。

### 10.4 项目 Project

- 项目名称、目标用户、问题、难度和预计周期。
- 产品方案、AI方案、项目步骤和完成标准。
- Prompt、测试数据、评测方法和错误案例。
- 作品集模板、项目表达和追问题库。

## 13. AI与自动化演进

### V1：结构化内容优先

- 人工整理和审核为主。
- AI辅助提取题目、标签和回答草稿。
- 使用关键词搜索和人工内容关联。

### V1.5：RAG检索

- 对已审核内容进行分块和索引。
- 按岗位、公司、主题和时间进行过滤检索。
- 回答必须附带引用和更新时间。

### V2：多智能体内容流水线

```text
采集/导入
→ 清洗去重Agent
→ 题目与知识提取Agent
→ 回答草稿Agent
→ 来源与一致性检查Agent
→ 人工审核
→ 发布
```

每个Agent只接收完成任务所需的资料，输出固定结构；系统不得跳过人工审核自动发布。

## 14. 数据指标

### 14.1 北极星指标

每周完成“项目核心步骤，并进入作品集或项目面试表达环节”的独立用户数。

### 14.2 关键过程指标

- 首页需求入口点击率。
- 知识内容完成率。
- 知识到项目的跳转率。
- 项目开始率和核心步骤完成率。
- 作品集模板复制/下载率。
- 面试题练习与关联项目访问率。
- 搜索无结果率。
- 内容更新频率和审核通过率。

### 14.3 首轮验证标准

使用至少30名目标用户进行测试：

- 80%以上能在10秒内说出网站帮助谁、解决什么问题。
- 80%以上能在2次点击内找到自己的需求入口。
- 50%以上会从知识内容进入关联项目或面试题。
- 30%以上开始至少一个实战项目。
- 参与项目测试的用户中，60%以上能按照模板形成一段3分钟项目介绍。

## 15. 内容质量与风险控制

### 15.1 内容质量

- 面试答案不能只给标准话术，必须说明考察目的和适用条件。
- 模型、论文与动态内容必须注明时间，避免过时内容继续作为结论。
- AI生成的事实、案例和引用必须经过人工检查。
- 不把博主个人经验包装成普遍招聘标准。

### 15.2 版权与来源

- 内部保存原始资料用于研究、去重和追溯。
- 前台优先发布提炼后的题目、框架和分析，不大段转载原文。
- 保留来源平台和原始链接。
- 对明确禁止转载或无法确认授权的内容，不展示完整截图和原文。

### 15.3 隐私

- 导入资料前移除手机号、微信号、真实姓名等无关个人信息。
- 不公开面试官和候选人的敏感身份信息。
- 用户未来上传简历或项目资料时，需要单独的隐私说明和删除机制。

## 16. MVP优先级

### P0：必须上线

- 首页需求目录。
- 两大核心板块及内容目录。
- 知识详情、面试题库和项目教程。
- 两个首发项目。
- 项目步骤本地进度。
- 作品集模板和项目表达内容。
- 关键词搜索与基础筛选。
- 内容后台、Excel导入、审核、关联和发布。

### P1：验证后增加

- 用户账号、收藏、笔记和跨设备进度。
- RAG问答和来源引用。
- AI辅助回答练习。

### P2：规模化后增加

- 模拟面试。
- 作品集辅助生成。
- 多智能体内容处理流水线。
- 个性化推荐。

## 17. 上线验收标准

V1达到以下条件即可进入种子用户测试：

- 首页六个需求入口全部可用。
- 两大板块目录和内容关联正常。
- 至少20篇核心知识内容达到统一模板要求。
- 至少50道结构化面试题完成来源和人工审核。
- 两个首发项目包含完整步骤、交付物、评测、作品集和面试表达。
- 管理员可以通过Excel导入资料，并完成编辑、预览、发布和下架。
- 站内搜索能区分知识、面试题和项目。
- 桌面端和移动端主要流程可正常使用。
- 原始资料不会未经审核直接展示到前台。

## 18. 产品结论

V1的核心不是“做一个内容很多的网站”，而是验证一条学习闭环是否成立：

> 用户能否从一个明确需求进入，学会必要知识，完成真实项目，并把项目转化为作品集和面试表达。

后台管理是V1的基础设施；RAG是内容成熟后的检索能力；多智能体是内容规模化后的效率工具。三者不能替代高质量、可验证、面向实际求职结果的内容。
