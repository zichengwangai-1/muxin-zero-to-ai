把好内容，变成能跟做的教程。

六个模块共用一套录入方式。不需要改代码，也不用重新排版。

一、第一次使用

线上使用 GitHub 登录，账号需有网站仓库写入权限。只有完成登录配置后才可在线保存。开发人员使用的本地模式不会发布到线上。

二、新增一篇内容

  1. 选择六个模块之一，点击新建。
  2. 填写固定 ID（例如 excel-monthly-report），保存后不要修改。
  3. 填写标题、分类、简介、完整 Prompt。按需补充成品图、准备材料、SOP、附件与来源。
  4. 先保存草稿，在预览中核对；未实测的内容不要标记为已实测。
  5. 确认后打开“发布后在网站展示”，保存并发布。等待部署状态显示成功，再查看网站。

图片模块需要成品图；05/06 有截图即可，无需演示链接。

三、导入 Markdown

下载标准模板。上传后会显示待导入字段，保存草稿时填入表单。固定 ID、所属模块和展示开关不被覆盖。普通 Markdown 仅作为补充正文，标题、分类、简介和 Prompt 需要单独填写。导入文件需小于 1 MB。

模板 module 可用 prompts、image、video、office、development、games。先进入对应模块，再导入。不要把未经整理的文章误当成完整 SOP。

四、图片、附件与下架

图片和附件单个不超过 10 MB。支持 PNG、JPG、WebP、GIF、PDF、DOCX、XLSX、PPTX、CSV、TXT、MD；不上传 HTML、脚本、压缩包或视频。视频模块使用 HTTPS 成片链接。

新内容下架：关闭“发布后在网站展示”并发布修改。旧内容：进入“已有资料 → 已有资料下架管理”选择要隐藏的条目，再发布。取消选择可恢复，不删除文件。

五、发布不等于网站已更新

保存草稿 → 内容存入草稿分支；发布 → 写入生产分支；Netlify 构建成功 → 网站更新。构建失败时线上保留上一版，请把错误反馈给开发人员，不要反复发布。

上线配置（首次由开发人员完成）

  1. 核验 Netlify 连接的仓库和生产分支，将分支写入 admin/site-settings.json 的 publishBranch。
  2. 在 GitHub 创建 OAuth App，回调地址为 https://api.netlify.com/auth/done；在 Netlify 的 OAuth 设置中安装 GitHub provider。
  3. Client Secret 只输入 Netlify 设置，不写入代码或聊天。审核登录权限，不开启公开投稿。
  4. 先审核当前本地未提交内容，再选择需要发布的文件。完成部署后验证管理员登录、草稿与一次正式发布。

在上述步骤完成前，这不是已经启用的线上后台。
