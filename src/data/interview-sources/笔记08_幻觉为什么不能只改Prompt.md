### 面试题

**模型输出不稳定，甚至会产生幻觉，你会怎么通过 Prompt 缓解？**

这道题虽然看起来是在问prompt，但真正考的，是你能不能判断问题发生在哪一层，并搭出一套可上线、可评估、可兜底的治理体系。

> **Prompt 能约束模型"怎么回答"，但不能独立证明模型"回答得对"。**

---

### 一、先别急着改 Prompt，先判断是哪类问题

实际业务里，大家常把所有错误都叫"幻觉"，但至少要拆成三类。

**第一类是输出不稳定。** 同一个问题多问几次，表达方式、字段顺序或结论发生波动。这类问题可能来自采样参数、指令歧义、上下文差异，也可能来自模型本身的不确定性。

**第二类是事实性幻觉。** 模型给出了流畅、确定，但缺少证据支撑甚至与事实冲突的内容。例如编造政策、数字、出处或产品能力。

**第三类是与幻觉相邻、但必须单独治理的安全边界失守。** 模型可能没有虚构事实，却在医疗、金融、法律等高风险场景给出了不该给的建议。这时只盯"幻觉率"，会漏掉更严重的问题。

我做搜索策略时，如果排查搜索结果异常，第一步通常不是马上改排序策略，而是先看问题出在召回、排序还是规则。这个习惯放到大模型产品里同样适用：检索没召回、知识已经过期、模型没有遵循证据、规则没有拦截，解决方案完全不同。

如果诊断错了，团队很容易陷入一个低效循环：模型一出错就改 Prompt，改完线上还有错，再继续堆指令。Prompt 越来越长，问题还是没找到。

**所以我建议先定位故障层，再讨论 Prompt 怎么改。**

---

### 二、三个"看起来很稳"的方案，其实都有边界

**1. 固定 JSON，只能保证结构，不保证事实。**

让模型按照固定字段输出，当然有价值。它能降低解析失败，方便后续系统消费，也能把"答案、证据、置信度"拆成可检查的字段。但格式正确，不等于内容正确。结构约束可以保证输出在语法和格式上合规，但字段中的值仍然可能需要业务校验。

> 一个结构完美的错误答案，甚至比一段明显混乱的文本更危险，因为下游系统更容易直接相信并执行它。

**2. 让模型自检，不等于独立验证。**

常见 Prompt 会在最后加一句："请检查以上回答是否存在事实错误。"

这能抓住部分粗心错误，却不能当作可靠兜底。原因很简单：写答案和检查答案的是同一个模型，这两个动作可能共享同一套知识盲区和推理偏差。

**3. 接入 RAG，也不代表问题消失。**

RAG 的价值，是让模型基于检索到的外部知识回答。但它至少还有两道风险：

- 检索层可能没有召回正确文档，或者召回了过期、冲突、权限不匹配的资料；
- 生成层可能拿到了正确资料，却忽略、曲解或过度外推其中的信息。

有些时候，即使已经提供了检索上下文，模型仍会产生与证据不一致或无证据支撑的内容。这也是为什么 AWS 在知识库评估里，会把检索质量和生成质量拆开：前者看相关性、覆盖率，后者看忠实度、正确性。

---

### 三、AI 产品经理要搭的是五层治理体系

面试时，我不会把回答停在 Prompt 层，而会把方案整理成五层：**定边界、找证据、控生成、做验证、跑闭环。**

#### 五层治理体系图

```
任务与风险边界（能做什么 / 不能做什么）
        ↓
上下文与证据质量（来源、时效、权限、冲突）
        ↓
生成约束（Prompt 限定回答行为）
        ↓
验证与降级（规则、工具、拒答、转人）
        ↓
评估、上线与监控（评测、灰度、反馈闭环）
```

#### 第一层：任务与风险边界

先定义模型能做什么、不能做什么，以及"答错"的代价。营销文案写得不够准确，可能只是影响体验；退款政策、用药建议、授信判断一旦答错，就可能造成真实损失。风险不同，治理强度不能一样。

这一层要明确：目标用户、任务范围、禁止回答的场景、必须转人工的条件，以及哪些结论允许模型生成，哪些只能从权威系统读取。

#### 第二层：上下文与证据质量

这一层解决的是"模型依据什么回答"。要管理知识来源的权威性、时效性、版本、权限和冲突关系；同时评估检索是否召回正确资料，而不是只看最终答案。

核心指标可以看检索召回率、相关性、有效证据覆盖率，以及过期或冲突文档的命中情况。

#### 第三层：生成约束

这才是 Prompt 发挥作用的地方。可以通过明确任务边界、限定只能使用给定资料、要求逐条引用证据、固定输出结构、规定信息不足时不得补全、将复杂任务拆成多个步骤等方式，减少模型自由发挥的空间。

但这里要记住：

> **Prompt 是行为约束层，不是事实校验层。**

这一层重点观察指令遵循率、引用完整率、格式通过率，以及回答与上下文的一致性。

#### 第四层：验证与降级

对高风险结论，不能让模型既当运动员又当裁判。

关键字段可以调用数据库、规则引擎或外部工具二次验证；关键陈述可以逐条匹配证据；无法验证时，产品要能够追问、拒答、降级为搜索结果，或者转人工。这里不能只统计"拦住了多少错误"，还要看误拒率。模型遇到任何不确定都拒答，幻觉率会很好看，但产品也基本没法用了。

#### 第五层：评估、上线与监控

离线评测不能只做一套"标准问答题"。至少要覆盖正常问题、模糊问题、缺少资料、冲突资料、过期资料、诱导编造和越权请求。

指标也不能只有一个幻觉率，而要形成一组制衡指标：

- 事实正确率、答案忠实度、引用准确率；
- 检索相关性、证据覆盖率；
- 错误拒答率、该拒不拒率；
- 任务完成率、用户采纳率；
- 延迟、推理成本和人工介入率。

上线后，再通过错误案例聚类、用户反馈、抽样审核和高风险告警持续更新评测集。

### 四、面试回答

如果只给三分钟，我会这样组织：

我会先区分输出不稳定、事实性幻觉和安全边界问题，因为三者的根因与治理手段不同。

Prompt 可以作为第一层缓解手段，包括限定资料范围、明确拒答条件、要求引用证据、结构化输出和自检。但 Prompt 主要约束模型怎么回答，无法独立保证知识正确，也无法修复检索缺失、资料过期或规则缺位。

所以我会搭五层体系：第一层定义任务和风险边界；第二层保证知识与检索质量；第三层用 Prompt 约束生成；第四层用规则、工具、人工审核做验证和降级；第五层建立离线评测、灰度上线和线上监控。

指标上，我不会只看幻觉率，还会同时看检索召回、回答忠实度、引用准确率、错误拒答率、任务完成率、延迟和成本。最终目标不是让模型"尽量少说"，而是在准确性、覆盖率、体验和成本之间找到符合业务风险的平衡点。

> "五层"叫什么并不重要。重要的是，你向面试官展示了四种能力：
> 1. 能先诊断，不把所有问题都塞进 Prompt；
> 2. 能从模型效果走到完整产品链路；
> 3. 能设计互相制衡的指标，而不是追求单一数字；
> 4. 能根据业务风险做取舍和兜底。

### 六、面试官继续追问，怎么接？

#### 追问一：拒答率越高，是不是幻觉治理越好？

不是。拒答能降低错误回答，但也会损害覆盖率和任务完成率。要同时看"该拒绝时是否拒绝"和"本来能答时是否误拒"，再按场景风险确定阈值。

#### 追问二：如果 RAG 召回了错误资料，怎么办？

不能只优化生成模型。要从数据源准入、文档版本、元数据过滤、召回与重排、冲突检测、答案引用和结果校验整条链路排查。高风险知识最好设置唯一权威源，而不是把所有文档无差别塞进知识库。

#### 追问三：自检到底要不要做？

要做，但要给它正确定位。自检适合发现格式遗漏、前后矛盾和部分推理错误；真正的事实验证，尽量依赖独立证据、外部工具或不同机制，而不是让同一次生成闭环自证。

---

### 写在最后

模型幻觉不是一个 Prompt 文案问题，而是一个系统可靠性问题。

会写 Prompt，是 AI 产品经理的基本功；知道 Prompt 什么时候有效、什么时候无效，以及失效后该由哪一层接住，才是更有区分度的能力。

面试里的高分回答，不是罗列最多的方法，而是建立一条完整的因果链：

> **先定义风险，再定位根因；用 Prompt 缓解，用系统验证，用指标制衡，用上线机制兜底。**
