# Demystifying Agent Skills：技能为什么有时有用，有时反而找不到？

## 一句话说清

Skill 最主要的价值不是给模型塞更多知识，而是把稳定步骤变成可复用流程；技能库越大，正确找出该用哪个技能反而越难。

## 论文要解决什么问题

大家知道 Skill 可能提升 Agent 表现，却不清楚它什么时候有效、为什么有效，以及技能库变大后为何经常无法正确调用。

## 它是怎么做的

研究在多个基准、模型和 Agent Harness 上控制技能表示、结果标注、检索难度和跨框架迁移，并分析 8,135 条标准化试验记录与成对执行轨迹。

## 关键发现

- Skill 在匹配比较中比 Workflow Memory 高 6.06 分；
- 65.7% 的有效案例来自“用流程稳定执行”，只有 4.5% 主要来自补充显式知识；
- 技能池从 5 个增长到 100 个时，实际使用精度从 29.6% 降到 3.3%；
- 常见失败包括前提过于脆弱、场景不兼容和缺少适配。

这些数字来自论文实验设置，线上效果仍需结合自己的任务验证。

## 小白怎么理解

一本“炒菜步骤卡”能帮助你稳定做菜，但抽屉里塞进一百张名字相似的卡片后，你可能连正确那张都找不到。

## 对 AI 产品经理的五层启发

### 1. 用户价值：Skill 应让结果更稳定，而不是显得更智能

用户不关心系统安装了多少技能，只关心常见任务能否少出错、少追问、重复使用。技能的价值应体现在流程稳定性和可预期性上。

### 2. 产品机制：把“发现”和“执行”分开设计

先根据用户意图筛出少量候选技能，再让模型选择和执行。技能名称、适用条件、输入输出和禁用条件要清楚，不能只写一段宽泛介绍。

### 3. 指标体系：既测调用，也测增益

- 正确技能的召回率与误触发率；
- 使用 Skill 相比不使用的成功率提升；
- 执行步骤遵循率；
- 技能库增长后的检索性能和额外成本。

### 4. 风险边界：错误 Skill 会稳定地做错事

流程越明确，错误触发后的影响也越稳定。涉及外部发送、删除和付款时，需要权限确认、预览和回滚，不能因为“这是标准技能”就自动放行。

### 5. 产品决策：少量高频、边界清楚的 Skill 优先

先覆盖高频且步骤稳定的任务，低频知识型内容更适合按需检索。技能库变大后，应投入到搜索、分层和淘汰，而不是继续追求数量。

## 如果落到真实产品

在办公 Agent 中，我会先做“周报整理、会议纪要转任务、竞品表格更新”三个 Skill。每个 Skill 写清触发条件、必要输入、输出格式和需人工确认的动作。只有当真实使用数据显示稳定增益后，才增加下一批。

## 面试参考答案

我最近读了 Demystifying Agent Skills。论文发现，Skill 的主要作用是把执行过程变成稳定的程序化锚点，而不是简单补知识；同时技能池从 5 个扩到 100 个后，实际使用精度明显下降。

所以我设计 Skill 产品时会先做少量高频流程，把适用条件和输入输出写清楚，并同时测检索是否正确、使用后成功率是否真正提升。涉及高风险动作还要加确认和回滚，避免错误 Skill 被稳定执行。

## 追问准备

### Skill 与 Prompt 模板有什么不同？

Prompt 模板通常只规范一次模型输入；Skill 更像完整操作说明，可能包含步骤、工具、检查和输出要求，并需要被正确发现和调用。

### 为什么技能越多越难用？

候选之间会变得相似，有限的描述和注意力不足以准确区分；因此需要分层检索、明确边界和淘汰机制。

## 一句话记忆

**Skill 的本事不是知道更多，而是把正确步骤做得更稳。**
