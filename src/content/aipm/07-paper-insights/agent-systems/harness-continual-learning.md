# Harness Continual Learning：Agent 自我改进，为什么也会越改越差？

## 一句话说清

即使模型完全不变，只要 Agent 修改了 Prompt、记忆、工具或路由，旧能力也可能被破坏；更新必须经过“新任务变好、旧任务不退步、规则仍有效”三道检查。

## 论文要解决什么问题

现代 Agent 会把执行反馈写入记忆、技能和规则，甚至自动调整工具路由。这些变化发生在模型参数之外，却同样会改变后续行为。新经验可能提高当前任务，也可能让以前稳定的任务突然失败。

## 它是怎么做的

论文提出 Harness Continual Learning，并把 Harness 状态拆为任务接口、经验记忆、能力地图和自适应路由。系统用 Continual Optimizer 提议修改，再由 Continual Evaluator 检查后决定是否正式写入。

评估同时关注当前改进、历史能力保留和修改后的有效性。

## 关键发现

论文在文本推理、多模态感知和开放世界交互中进行实验，多项设置相对基线提升超过 10%，同时通过受控实验展示了可测量的 Harness 层遗忘，以及稳定与适应之间可以调节的取舍。

这是研究原型的实验结果，不代表自动修改 Harness 已适合直接用于所有生产系统。

## 小白怎么理解

给公司流程增加一条新规定，可能解决今天的问题，却与去年的规定冲突。Agent 的自我改进也需要先在测试环境审核，不能想到什么就直接改正式规则。

## 对 AI 产品经理的五层启发

### 1. 用户价值：持续学习必须保持行为可预期

用户愿意让 Agent 越用越懂自己，但不愿它昨天会做、今天突然不会。产品要让用户知道哪些偏好被学到，并允许查看、撤销和重置。

### 2. 产品机制：提议与生效必须分离

新记忆、Prompt 或路由先成为候选版本，在沙箱中运行当前任务和历史回归集；只有达到门槛才生效，失败则保留旧版本。

### 3. 指标体系：同时测学习和遗忘

- 当前新任务的提升；
- 历史核心任务的退化率；
- 错误记忆或规则冲突率；
- 候选更新的通过率、回滚率和长期净收益。

### 4. 风险边界：用户反馈不一定是正确监督

一次负面反馈可能来自误操作、临时偏好或恶意输入。系统不能把单次反馈永久写入全局规则，高风险修改需要更多证据或人工确认。

### 5. 产品决策：先做可撤销的个性化，再做自动改写系统

早期可以让用户明确保存偏好并提供版本历史；积累足够数据后，再尝试自动提出改动。自我修改范围越大，评测和回滚能力必须越强。

## 如果落到真实产品

在销售助理中，用户说“以后邮件短一点”可以先作为个人候选偏好，只影响草稿并可一键撤销；不能直接改掉全团队品牌规范。每次更新还要在历史客户和不同语气任务上回归测试。

## 面试参考答案

我最近读了 Harness Continual Learning。它提出一个容易忽略的问题：模型参数不变，Prompt、记忆、技能或路由的更新仍然会让 Agent 遗忘旧能力。论文把改动提议和正式生效分开，只有当前提升、历史保留和有效性都通过检查才提交。

对产品经理来说，自我学习功能必须和版本、评测、回滚一起设计。我会先从用户可见、可撤销的偏好开始，用新任务收益和旧任务退化率共同决定是否生效，而不是只看当前一次反馈。

## 追问准备

### 与模型微调后的灾难性遗忘有什么区别？

传统遗忘发生在模型参数中；这里模型可以冻结，丢失来自 Prompt、记忆、工具或路由的变化，但用户看到的结果同样是旧能力退化。

### 所有改动都要人工审核吗？

不需要。低风险个性化可以自动灰度并支持回滚，高风险全局规则则需要人工审核；关键是风险分级。

## 一句话记忆

**Agent 会学习，也会忘；每次进步都要带着旧题重考。**
