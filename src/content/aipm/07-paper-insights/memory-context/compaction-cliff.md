# Compaction Cliff：为什么 Agent 越聊越久，越容易忘掉安全规则？

## 一句话说清

统一压缩上下文会把必须逐字保留的安全规则和普通历史一起改写；信息类型不同，压缩和召回策略也必须不同。

## 论文要解决什么问题

Agent 上下文快满时会压缩旧内容，但普通经历可以概括，安全规则、合同条款和格式约束却可能因为一个词被改掉就失效。统一摘要没有识别这种差异。

## 它是怎么做的

论文提出 Knowledge Triage：先给知识逐行分类，再按类型采用不同策略。

- TypeCompact：按信息类型设置不同保真度；
- TypeDecompose：内容太大时拆分，并把相关安全规则带到每一块；
- TypeRetrieve：从外部存储取回内容时，先固定必须执行的规则，再按相关性补充信息。

## 关键发现

作者在 20 种生产 Agent 配置上测试，报告 Claude Code 的压缩在一次后保留 53% 的安全规则，五次后只剩 10%。Knowledge Triage 在五个公开语料上保留的安全规则是强单次压缩基线的 2–4 倍，并在五轮后达到 96% 召回率。

这是论文所测配置的结果，不能直接代表所有模型和压缩方式。

## 小白怎么理解

整理行李时，衣服可以压缩，护照和药品说明不能剪掉一半。所有信息用同一种“省空间方法”，重要规则就会丢失。

## 对 AI 产品经理的五层启发

### 1. 用户价值：关键规则必须跨长任务稳定生效

用户不会接受 Agent 前半程守规矩、后半程突然忘记。产品需要向用户说明哪些约束被长期固定，并允许查看和修改。

### 2. 产品机制：给上下文增加信息类型和优先级

至少区分安全规则、用户偏好、事实证据、任务状态和临时过程。安全规则保留原文，事实保留来源，偏好允许用户更新，临时过程才可以积极压缩。

### 3. 指标体系：把多轮衰减单独测出来

- 第 1、3、5 次压缩后的规则保留率；
- 规则存在时的真实行为遵守率；
- 无关规则被错误带入的比例；
- 压缩率、成本与任务成功率。

### 4. 风险边界：召回到规则不等于执行了规则

系统既要测规则是否仍在上下文中，也要测试 Agent 是否真的遵守。高风险操作还需要确定性权限校验，不能只依赖自然语言规则。

### 5. 产品决策：先保护不可逆的信息

安全、权限、法律限制和用户明确禁止事项优先采用不可压缩或确定性校验；其他内容再按价值与成本做分层压缩。

## 如果落到真实产品

在企业采购 Agent 中，预算上限、供应商黑名单和审批要求应固定在策略层；沟通历史可以摘要；商品搜索结果可以过期。每次压缩后自动跑一组规则遵守测试，失败就恢复旧上下文或停止任务。

## 面试参考答案

我最近读了 Compaction Cliff。论文发现，长任务中统一压缩会快速损失安全规则，五轮后某个生产配置只保留 10%。它提出先识别信息类型，再为规则、事实和过程使用不同的压缩、拆分和检索策略。

对产品经理来说，这意味着上下文管理不是纯粹省 Token，而是信息治理。我会把安全和权限规则放在不可压缩的策略层，对多轮压缩做回归测试，并用确定性校验保护不可逆操作。

## 追问准备

### 规则全部置顶不就可以了吗？

少量核心规则可以置顶，但规则多时仍会占满上下文并互相冲突，需要分类、按场景启用和确定性权限控制。

### 为什么摘要会破坏规则？

摘要追求语义简洁，而规则常依赖精确条件、例外和否定词；意思“大致相同”并不足以保证行为相同。

## 一句话记忆

**历史可以概括，红线必须原样保留。**
