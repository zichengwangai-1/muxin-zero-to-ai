# PM-Bench：Agent 为什么会忘记“以后再做”的事？

## 一句话说清

PM-Bench 专门评测 Agent 能否一边处理当前任务，一边记住在未来某个时间或条件出现时执行之前的约定。

## 论文要解决什么问题

普通记忆评测通常问“之前说过什么”，但真实助理还要记住“以后要做什么”。例如收到回复后提醒我、价格低于某值时购买、周五提交报表。这种能力叫前瞻记忆。

## 它是怎么做的

论文设计了一个模拟七天的文本环境。Agent 要持续进行日常活动，同时观察未来任务是否已经到时间或满足触发条件。研究比较八个模型和八种 Agent 配置。

## 关键发现

最佳方案——论文中的 GPT-5.4 Agent——也只达到 65.1% F1；而且没有一种提升前瞻记忆的方法能在所有模型上持续占优。

## 小白怎么理解

记得朋友生日是哪天，是回忆事实；到了生日当天主动提醒你买礼物，是前瞻记忆。AI 会聊天不代表它能可靠地等到条件满足再行动。

## 对 AI 产品经理的五层启发

### 1. 用户价值：主动助理的价值来自“到点真做”

用户愿意把任务交给 Agent，是因为不想一直盯着。漏提醒一次重要事项，就可能摧毁对整个产品的信任。

### 2. 产品机制：意图、触发器和动作要结构化

不能只把“以后提醒我”留在聊天文本中。系统需要明确记录做什么、何时或在什么条件下触发、需要哪些权限、失败后如何处理。

### 3. 指标体系：前瞻任务有自己的成功标准

衡量触发召回率、错误触发率、执行延迟、重复执行率、任务取消是否生效，以及执行失败后是否成功通知用户。

### 4. 风险边界：主动执行必须可控

提醒与发消息的风险不同，发消息与付款的风险也不同。高风险动作应在触发后再次确认，且用户随时能查看、修改和取消待办意图。

### 5. 产品决策：模型负责理解，确定性系统负责守时

模型适合把自然语言转成任务结构、理解复杂条件；真正的计时、状态监听、幂等和重试应交给确定性任务系统，而不是期待模型一直记着。

## 面试参考答案

PM-Bench 研究的是前瞻记忆，也就是 Agent 能否记住未来要执行的意图。它用模拟七天的环境测试模型，最佳配置也只有 65.1% F1，说明会理解对话不等于能可靠地到点行动。

对产品经理来说，主动助理不能把未来任务只存成一段聊天记录。我会把它拆成意图、触发条件、动作、权限和失败策略，由模型理解用户表达，确定性任务系统负责监听和执行。指标则看漏触发、误触发、延迟和重复执行。金额、发信等高风险动作在触发后必须再次确认。

## 追问准备

### 为什么不用模型自己记住？

模型不会持续运行并可靠监听现实状态；对话上下文也可能被压缩或丢失。时间和条件触发需要专门的任务系统。

### 怎样避免重复执行？

给每个任务唯一标识，记录执行状态，并保证同一触发事件只产生一次有效动作。

## 一句话记忆

**模型负责听懂“以后做什么”，系统负责保证“到时候真做”。**
