# AeroCopilotBench：为什么“懂知识”不等于“会安全执行”？

## 一句话说清

这篇论文用虚拟驾驶舱评测航空 Agent，发现静态知识成绩并不能稳定转化为实际操作能力，完成任务与全程安全必须分开检查。

## 论文要解决什么问题

许多 Agent 评测仍然是问答题：模型知道流程、术语和规则，就被认为具备能力。但真实场景需要读取当前状态、按顺序操作工具、检查反馈，并且任何一步都不能违反安全约束。

## 它是怎么做的

研究者建立了两层评测：第一层用 1,200 道选择题测试航空知识；第二层让 Agent 在交互式虚拟驾驶舱中完成 73 个紧急或异常任务。只有同时完成目标且没有触碰硬性安全约束，任务才算成功。

## 关键发现

- 12 个模型中，第二层最高成功率为 72.6%；
- 静态知识表现不能稳定预测实际操作表现；
- 451 个失败案例中，常见问题包括流程不完整、没有利用状态反馈，以及长流程管理失败。

## 小白怎么理解

背得出驾考题，不代表真的会在路上安全开车。AI 也可能把操作步骤说得很漂亮，但执行时漏一步、顺序错了，或者完成目标却违反安全规则。

## 对 AI 产品经理的五层启发

### 1. 用户价值：用户购买的是可靠完成，不是知识表演

在客服、财务、医疗和企业操作中，用户并不在乎 Agent 能否解释概念，而是在乎它能否完成任务且不制造新风险。

### 2. 产品机制：状态必须进入决策回路

Agent 每次行动后都要读取环境反馈，再决定下一步。产品不能只生成一份完整计划后机械执行，而要设计“观察—判断—行动—复核”的闭环。

### 3. 指标体系：目标完成与过程安全分开看

至少分别衡量任务完成率、步骤完整率、违规率、状态识别准确率、人工接管率。一个任务即使完成，只要触碰硬约束，也不应该被记录为成功。

### 4. 风险边界：硬规则不能只写在 Prompt 里

重要权限、金额、删除操作和安全限制应该由系统层校验。Prompt 可以提醒，但确定性的规则必须在执行层阻断，并留下审计记录。

### 5. 产品决策：先限定场景，再扩大自主性

新产品不应一开始就承诺全自动。可以从可回退、可验证的低风险任务开始，通过失败案例建立检查规则，再逐步开放更长流程和更高权限。

## 面试参考答案

AeroCopilotBench 给我的核心启发是，Agent 评测要从“会不会回答”升级到“能否在真实状态中安全完成”。论文发现航空知识得分不能稳定转化为操作成功，最高的交互任务成功率也只有 72.6%。

如果我做企业 Agent，我会把评测拆成三层：知识是否正确、任务是否完成、全过程是否违反硬规则。产品上采用状态反馈闭环，每一步执行后重新读取环境；高风险操作由系统规则拦截并要求人工确认。这样能避免出现答案看起来专业、实际执行却不可靠的问题。

## 追问准备

### 为什么不能只看任务完成率？

因为 Agent 可能通过危险或违规路径得到正确结果。完成率只回答“到没到终点”，不能回答“怎么到的”。

### 什么是硬安全约束？

一旦违反就必须判失败的规则，例如未经确认转账、删除关键数据、绕过权限或执行不可逆操作。

## 一句话记忆

**会背操作手册，不等于会安全地把事情做完。**
