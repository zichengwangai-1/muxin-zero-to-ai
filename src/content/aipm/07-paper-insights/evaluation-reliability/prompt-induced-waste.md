# Prompt-Induced Waste：同一个任务，为什么一句话能让 Agent 贵很多？

## 一句话说清

Prompt 不只影响答案，也会改变 Agent 的思考长度、工具调用和验证次数；评估效率必须看“每次成功花多少钱”，不能只看 Token 单价。

## 论文要解决什么问题

团队常用 Token 数或模型价格衡量 Agent 成本，却忽略了 Prompt、推理强度、运行框架、工具和任务难度会共同改变整条执行轨迹。

同一个任务即使最终都做对，也可能一个只走必要步骤，另一个反复提出方案、调用工具和验证，成本相差很大。

## 它是怎么做的

研究在确定性编程任务上控制模型、任务和运行框架，改变 Prompt 表达与推理要求，比较任务成功、推理、工具调用、轮次、延迟和端到端成本。

论文把核心指标定义为“每个成功任务的成本”，而不是孤立比较 Token 数。

## 关键发现

作者的控制实验显示，Prompt 措辞可以改变推理与验证行为，却不一定改变任务正确率；同一种效率策略换到不同运行框架后，收益也可能变化。论文因此强调：Prompt、推理强度和 Harness 是相互影响的实验变量。

论文为 arXiv 预印本，结论来自编程 Agent 场景，迁移到客服、搜索等产品时需要重新实验。

## 小白怎么理解

你让同事“完成表格”和“先想五种方案，逐一验证，确保绝对正确后完成表格”，最终文件可能一样，但第二种说法会让过程更长、更贵。

## 对 AI 产品经理的五层启发

### 1. 用户价值：把等待和费用一起纳入体验

用户需要的是正确完成任务，不是看到 Agent 很忙。多轮思考只有在明显提高成功率时才有价值；否则只是把不确定感包装成更多步骤。

### 2. 产品机制：按任务难度动态分配推理预算

简单任务使用短路径，复杂或高风险任务再增加规划、复核和更强模型。Prompt 应明确目标、边界、验收标准和停止条件，减少没有价值的发散。

### 3. 指标体系：看成功任务的完整成本

- 成功率与一次完成率；
- 每个成功任务的模型、工具和基础设施成本；
- 平均完成时间与无效步骤数；
- 返工率，以及额外推理带来的成功率增量。

### 4. 风险边界：不能为了省钱删掉必要验证

医疗、金融、代码发布等任务需要更多检查。产品经理要区分“重复验证”和“风险所需验证”，并用风险等级决定最小检查清单。

### 5. 产品决策：先做小规模对照实验再改默认 Prompt

同一模板在不同模型和 Harness 上可能表现不同。上线前要固定任务集，对比成功率、总成本和时延，再决定是否作为默认策略。

## 如果落到真实产品

对于 AI 办公助手，我会把任务分成“改写一句话、总结文档、跨系统完成流程”三级。第一级禁止多方案发散；第二级增加事实核验；第三级才启用规划、工具重试和最终验收，并为每级设置最大步骤与停止条件。

## 面试参考答案

我最近读了 Prompt-Induced Waste。它提醒我，Prompt 不只是内容设计，也是成本和流程设计。相同任务下，不同措辞会改变 Agent 的思考、工具调用和验证行为，但更多计算并不必然带来更高成功率。

如果负责 Agent 产品，我会用“每个成功任务的端到端成本”而不是 Token 单价做核心效率指标，并按任务难度设置不同推理预算。默认 Prompt 会写清范围、验收标准和停止条件，再通过固定任务集做对照实验，确保节省成本没有牺牲成功率。

## 追问准备

### 怎样判断某一步是浪费？

移除这一步做对照实验；如果成功率和风险指标没有变差，而成本和时延下降，它才可以被判定为冗余。

### 为什么不能只看 Token 数？

工具费用、沙箱时间、失败重试和缓存计费都会影响真实成本，Token 只是执行轨迹的一部分。
