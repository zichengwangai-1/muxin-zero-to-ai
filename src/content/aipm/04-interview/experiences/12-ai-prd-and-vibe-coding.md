# AI PRD 与 Vibe Coding：产品经理需要讲到什么程度

**来源性质**：根据已收集的 AI PRD、AI Coding 与原型制作经验整理。原资料中的具体工具只代表使用示例，本页重点是通用能力。

## 面经里问了什么

- AI 产品的 PRD 和传统 PRD 有什么不同？
- 为什么一定要用大模型，规则或传统功能能否解决？
- Workflow、模型、Prompt、数据集、评测与兜底如何写入方案？
- AI 产品经理需要具备怎样的 Vibe Coding 能力？
- 如何把模糊想法变成可运行的原型？

## 考察点

- 能否把用户价值、系统行为和效果标准写成团队可执行的文档。
- 是否知道 Prompt、模型和评测也需要版本管理与验收。
- 是否能用自然语言拆解需求，并理解前端、后端、数据库、API、鉴权、状态和部署的基本关系。

## 小白怎么理解

AI PRD 不是在传统 PRD 后面加一句“接入大模型”。因为同一个输入可能得到不同输出，PRD 还要说明模型负责什么、什么叫好、失败如何处理、成本和延迟能否接受。

Vibe Coding 也不是让 AI 随便生成代码。产品经理的价值仍然是把目标、范围、流程、异常和验收标准说清楚，并能判断结果是否真的满足需求。

## 参考答案

### AI PRD 九个部分

1. 用户问题、业务价值与为什么必须使用 AI。
2. 业务目标、模型效果目标和风险红线。
3. 用户流程、系统流程和 Agent Workflow。
4. 模型选型、路由与成本延迟约束。
5. Prompt 内容、版本与发布规则。
6. RAG 或训练数据的来源、质量和权限。
7. 评测集、Rubric、执行方式和验收阈值。
8. 失败、降级、转人工、安全和监控。
9. 灰度、实验、数据回流与迭代计划。

### Vibe Coding 三个实用等级

1. **会提需求**：把模糊想法拆成明确任务、范围和验收。
2. **会拆复杂任务和管理上下文**：先搭框架，再逐个完成页面、数据和接口。
3. **会基础调试**：能判断问题来自界面、接口、数据、权限还是部署，并读取错误信息与日志。

达到第三层，通常已经能够独立制作并验证小型产品；复杂生产系统仍需要专业工程协作。

## 追问延伸

- AI 生成的原型能直接上线吗？不能默认。还需检查安全、性能、数据、兼容、可维护性和真实用户流程。
- Prompt 要不要写进 PRD？关键 Prompt、变量、版本、测试和发布条件应被管理，但具体归属可按团队流程决定。
- 所有 AI 节点都用同一模型吗？应按任务难度、风险、速度和成本路由。

## 一句话记忆

**AI PRD 多写三件事：模型做什么、怎样算做好、做不好怎么办。**
