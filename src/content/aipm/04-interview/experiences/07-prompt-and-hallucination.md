# Prompt 与幻觉治理：不要把所有问题都推给提示词

**来源性质**：根据已收集的 Prompt 写作、AI 交互设计与幻觉治理内容整理。参考答案合并了多份资料中一致的逻辑，并将容易误解的术语改成小白可读的表达。

## 面经里问了什么

- 如何设计并迭代一个 Prompt？
- 如果负责小红书风格文案生成器，Prompt 怎么设计？
- 同一个 Prompt 在不同模型上的结果为什么不同？
- 系统提示词、示例、温度等如何影响输出？
- 幻觉为什么不能只靠改 Prompt 解决？
- 拒答率越高，是否说明幻觉治理越好？
- 如果 RAG 召回了错误资料怎么办？模型自检要不要做？

## 考察点

- 能否把模糊风格转成可观察、可测试的要求。
- 是否理解 Prompt 是产品的一部分，需要版本、测试和发布管理。
- 是否能判断错误根因在任务、上下文、检索、模型还是验证环节。
- 是否能平衡回答覆盖率、正确率和用户体验，而不是一味拒答。

## 小白怎么理解

Prompt 像交给新同事的任务单：要说清做什么、为什么做、有哪些材料、遵守什么限制、最后交付什么格式。它能减少沟通歧义，但无法把错误资料变正确，也无法让模型获得它本来不会的知识。

幻觉也不等于“模型故意撒谎”，而是生成了看起来合理、实际没有依据的内容。原因可能来自任务太开放、资料错误、检索漏召回、上下文冲突、模型能力不足或产品没有验证机制。

## 参考答案

### Prompt 三条基本原则

1. **明确**：写清任务、目的和判断标准，不假设模型知道隐含背景。
2. **具体**：用正向、可执行的要求代替“不要写得不好”等模糊限制。
3. **结构化**：把角色、任务、背景、材料、要求、限制和输出格式分块。

设计风格型 Prompt 时，先分析真实优质样本，把“活泼、有网感”拆成标题结构、句长、语气、段落、Emoji 频率和禁用表达；再提供少量高质量示例，并通过用户重做、修改和采纳数据持续迭代。

### Prompt 的产品化闭环

建立版本号与变更记录；维护覆盖典型、边界和高风险场景的测试集；每次修改前后跑相同用例；达标后灰度发布；上线后把新 Bad Case 回流。不要在生产环境里凭感觉不断加句子。

### 幻觉五层治理

1. **任务与风险边界**：高风险问题是否应该回答，哪些必须拒答或转人。
2. **上下文与证据**：资料是否正确、完整、最新，检索是否找对内容。
3. **生成约束**：要求引用、限定格式、证据不足时明确说明不知道。
4. **验证与降级**：规则校验、工具核验、二次模型检查、转人工。
5. **评测与监控**：持续测幻觉、拒答、引用和业务结果，分析新 Bad Case。

拒答率不是越高越好。过度拒答虽然降低错答，却会损害覆盖率和任务完成。应该按风险分级，为高风险设置更严格阈值，为低风险保留澄清和有限回答。

## 追问延伸

- RAG 召回错误资料怎么办？从数据源、版本、切分、召回、排序和权限逐层检查，并要求答案引用可追溯。
- 自检是否一定有效？不一定。同一模型可能重复原错误，需用工具、规则、不同模型或人工抽检交叉验证。
- 温度调低能消除幻觉吗？只能提高输出稳定性，不能修复错误知识或证据缺失。

## 一句话记忆

**Prompt 管“怎么说和怎么做”，证据、验证与兜底共同决定“能不能信”。**
