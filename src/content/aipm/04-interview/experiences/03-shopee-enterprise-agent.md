# Shopee AI 产品一面：企业知识库 Agent 如何讲完整

**来源性质**：根据已收集的 Shopee AI 策略产品经理一面记录整理。原记录主要提供问题清单，没有公开逐题回答；以下答案为面试准备框架。

## 面经里问了什么

1. 介绍实习经历与求职地点选择。
2. 为什么做企业知识库 Agent？解决什么问题？如何接入原有工作流？
3. Agent 基于什么平台开发？RAG 使用什么 Embedding 和向量存储？
4. 你负责什么？Top K 等参数如何调整？
5. 项目怎么测试和迭代？评测集如何构建、运行和人工标注？如何判断准确性与幻觉？
6. 简历筛选产品的工作流、图片型 PDF 识别、Prompt 维护与模型选择是什么？
7. 企业知识库定时推送如何实现？还有什么优化空间？
8. 群聊推送如何满足个性化，同时避免打扰其他人？
9. 内部 B 端 Agent 与普通用户使用的 C 端 Agent 有什么区别？
10. 面对“帮我整理最近的工作”这类模糊需求，Agent 如何理解用户？
11. 平时使用哪些 AI 开发工具？
12. 用户要求监控下周三的航班变化并及时提醒，产品和 Workflow 怎么设计？

## 考察点

这组问题从项目真实性一路追到系统细节：业务价值、工作流接入、检索参数、评测、非结构化文档、主动触达、个性化与长期任务。面试官想确认候选人能否把 Agent 当成完整产品，而不是一个聊天页面。

## 小白怎么理解

企业知识库 Agent 的难点通常不在“接上大模型”，而在于资料是否可用、权限是否正确、答案能否引用证据，以及它是否真的进入员工原来的工作流程。

Top K 也不是越大越好。取太少可能漏答案，取太多会带来噪音、延迟和成本。应在真实评测集上比较召回率、答案正确率、响应时间和费用，而不是凭经验固定一个数字。

## 参考答案

### 企业知识库项目六段式

1. **问题**：员工在哪个流程中耗时，现有搜索为什么解决不了。
2. **数据**：知识来自哪里，如何切分、更新、授权和追踪版本。
3. **检索**：Query 改写、多路召回、融合、Rerank 与引用如何组合。
4. **生成**：Prompt 如何约束答案、引用和拒答。
5. **评测**：真实问题集覆盖哪些场景，怎样定义正确、完整和安全。
6. **上线**：接入什么工作流，如何灰度、收集反馈与回流 Bad Case。

### B 端与 C 端 Agent 的差异

| 维度 | 内部 B 端 | 面向消费者的 C 端 |
|---|---|---|
| 核心价值 | 提升流程效率与组织知识复用 | 低门槛体验、即时价值与留存 |
| 数据 | 企业私有数据多，权限复杂 | 用户个人数据与公开内容较多 |
| 风险 | 权限越界、错误操作、审计 | 误导、隐私、内容安全与信任 |
| 交互 | 可接受一定学习成本，强调工作流融合 | 要求更自然、快速、少配置 |
| 指标 | 任务完成率、节省工时、采用率 | 激活、留存、满意度、付费 |

### 航班监控 Agent

先收集航班号、日期、出发机场、通知渠道和提醒偏好；再通过可信航班数据源定时检查状态。只有状态变化时触发通知，避免重复打扰。对取消、延误、登机口变化设置不同优先级，并允许用户暂停任务。数据源失败时要提示“暂时无法确认”，不能把旧状态当成最新状态。

## 追问延伸

- 图片型 PDF 如何处理？需要 OCR、版面分析、表格与图片提取，并保留页码等引用位置。
- 群聊里如何减少打扰？默认摘要、订阅制、@指定用户、频率限制与静默时段。
- 如何理解模糊任务？先识别缺少的时间范围、资料范围和输出标准，再用最少问题澄清。

## 一句话记忆

**企业 Agent 要讲完整：知识从哪来、谁能看、怎么找、答错怎么办、怎样进入真实工作流。**
