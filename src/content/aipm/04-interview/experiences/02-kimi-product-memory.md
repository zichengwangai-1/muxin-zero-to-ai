# Kimi 产品岗一面：项目产品化、搜索与 Memory 设计

**来源性质**：根据已收集的一份 Kimi 产品岗一面记录整理。原记录没有公开所有问题的标准答案，下面的参考答案是基于原题补充的准备框架。

## 面经里问了什么

- 你的职业规划是什么？更想做产品、开发还是算法？
- 这套流程如何产品化？面向谁？用于什么业务场景？
- 即使获得全部生理数据，如何量化情绪并建立框架？
- 哪个项目实践最深？如果跨设备传输结合 AI，选择什么技术路线？
- 电子日记的输入如何做到低摩擦？还能收集哪些行为数据？
- 日记内容应该用什么框架整理和分类？
- AI 产品的历史搜索页如何优化，并沉淀优质内容？
- 你使用过的 AI 产品中，Memory 体验如何？怎么改？
- 学习状态与休假状态发生记忆冲突时，如何处理？

## 考察点

- 能否把个人项目从“技术演示”转成明确的用户、场景、价值和产品流程。
- 面对开放问题时，能否先搭框架，再逐层提出可验证的方案。
- 是否理解 Memory 不只是“保存聊天”，还涉及提取、更新、冲突、遗忘、权限和用户控制。
- 是否能识别数据并非越多越好，还要考虑采集成本、准确性、隐私和可解释性。

## 小白怎么理解

这类面试没有唯一答案。面试官不是期待你猜中 Kimi 内部方案，而是在看你遇到模糊问题时会不会先建立判断标准。

例如“日记输入怎么做到零摩擦”，不能只回答增加语音输入。你要先理解用户为什么懒得记录：不知道写什么、输入耗时、担心隐私，还是记录后没有回报。不同原因对应不同方案。

## 参考答案

### 把项目讲成产品，而不是 Demo

回答“如何产品化”时，至少讲清六件事：目标用户、核心场景、现有替代方案、AI 不可替代性、最小闭环和成功指标。先选一个窄场景验证，不要一开始说服务所有人。

### 历史搜索如何沉淀价值

可以拆成四层：

1. **找得到**：按项目、时间、来源和主题筛选。
2. **看得懂**：保留问题、关键结论、引用与上下文，而不是只留标题。
3. **能复用**：支持收藏、继续追问、加入项目空间或生成新任务。
4. **会治理**：过期内容提醒、敏感内容权限、重复结果合并。

### Memory 冲突怎么处理

先区分记忆类型：用户明确设置的偏好、长期稳定事实、某个项目里的临时上下文、模型推测出的偏好。优先级通常应为：用户明确指令 > 当前场景 > 经确认的长期偏好 > 模型推测。

当“学习状态”和“休假状态”冲突时，不应偷偷覆盖旧记忆。产品可以识别当前情境、向用户确认，或建立场景化偏好；同时提供查看、修改和删除记忆的入口。

### 情绪量化怎么答

先定义业务目的：是做健康提醒、内容推荐还是情绪日记？再组合主观自评、行为信号和生理数据，并说明标签噪声、个体差异与隐私限制。输出更适合表达为概率或趋势，不应把模型推断包装成医学结论。

## 追问延伸

- **Memory 越多越好吗？** 不是。无关或过期记忆会污染上下文，还会增加成本和隐私风险。
- **如何验证零摩擦输入真的有效？** 观察首次记录完成率、单次输入耗时、持续记录率和用户主动修改率。
- **AI 搜索页的北极星指标是什么？** 不能只看搜索次数，应结合任务完成、结果复用和后续行动。

## 一句话记忆

**Memory 不是把所有话都记住，而是在对的场景调用对的、可由用户控制的信息。**
