# 腾讯 AI 产品面试：业务流程、RAG 幻觉与学生 Agent

**来源性质**：根据已收集的一份腾讯 AI 产品面试经历整理。原作者只有传统产品实习背景，并分享了自己在项目追问中的真实应答；具体招聘结论不作为本页学习内容。

## 面经里问了什么

- 如何定义 AI 业务场景？
- 你日常如何设计自己的 AI Workflow？
- RAG 的幻觉怎么处理？
- 设计一个面向学生场景的 Agent。
- 你是否真的做过 Agent，遇到过什么问题？

## 考察点

虽然岗位带有 AI，面试官仍然重视传统产品的需求分析和流程拆解；技术概念必须与亲自做过的项目、调试和指标连接起来。

## 小白怎么理解

原记录中真正打动面试官的不是候选人背了多少 Agent 概念，而是他能讲出自己如何从需求到评测跑完一个 RAG Agent 项目，以及为改善幻觉反复调整检索切片的过程。

这里要注意：一段经历里的准确率变化只属于那个项目，不能直接变成所有 RAG 产品的目标，也不能在自己的面试中照搬数值。

## 参考答案

### 如何定义 AI 业务场景

先描述用户当前任务、频率、失败代价和替代方案；再判断 AI 在理解非结构化信息、生成、检索或动态决策上是否带来明显增益；最后确认数据、评测、成本和风险是否可控。

### 学生 Agent 怎么设计

先收窄场景，例如“根据错题生成一周复习计划”，不要泛化成全能老师。能力链可包括：读取经过授权的学习数据、识别薄弱知识点、制定计划、调用题库、跟踪完成情况和根据反馈调整。关键约束包括未成年人隐私、答案可靠性、教师或家长控制、拒绝替考，以及失败时回到普通学习工具。

### RAG 幻觉怎么处理

把问题拆成资料、切分、召回、排序、生成和交互六段。答案必须引用证据；没有足够证据时先澄清或拒答；通过真实问题与历史失败构建评测集，持续验证调整是否真的有效。

## 追问延伸

- 学生 Agent 如何避免让用户偷懒？把目标设计为提示、练习和反馈，而不是直接代做。
- Workflow 和 Agent 怎么选？固定步骤优先工作流，需要动态判断和多工具协作时再使用 Agent。
- 项目数据不够怎么办？先收窄任务，用人工审核和小规模真实样本建立第一版评测。

## 一句话记忆

**AI 岗也先考产品基本功：场景要真、流程要清、项目要能经得起追问。**
